# SoundCloud Wave: мобильный клиент (Android)

Нативный клиент на Expo (React Native, TypeScript, Expo Router). Вход через WebView на soundcloud.com,
данные из api-v2, звук через react-native-track-player (HLS). Логика «Моей волны» переносится из
desktop-клиента (`../src/services`), чистые модули копируются в `src/core`.

## Что переносим из desktop

| Desktop | Мобильный клиент |
|---|---|
| Плеер сайта (webpack-хук) | react-native-track-player, очередь своя |
| `callEndpoint` сайта | свой клиент api-v2 с токеном из входа |
| `node:sqlite` (история, рекомендации) | `expo-sqlite` |
| `wave.ts` в DOM страницы | экраны React Native + `src/core` |
| Радар релизов | `radar.ts` + фоновая задача и уведомление |
| Адблок, Discord RPC, thumbar, GPU, автообновление | не нужны |

## Этапы

0. Каркас Expo и сборка APK в GitHub Actions.
1. `src/core`: типы, трек-идентичность, жанры, настроение, вкус, подбор, диспетчер запросов, i18n.
2. Вход и API-клиент.
3. Плеер: HLS, очередь, фон, уведомление, сохранение сессии.
4. Экраны: главная, поиск, библиотека, артист, меню трека.
5. «Моя волна».
6. Вкус и история (SQLite), «Моя музыка».
7. Подборки дня, радар релизов (по запросу), чарты, плейлисты, набор из меню трека.
8. Доработка вкуса: «убрать из вкуса», штраф пресета за пропуски, признак серии пропусков (П7), развилка «Куда дальше?» (П8).
9. Настройки и «аддоны»: язык, аккаунты, инкогнито, вебхуки, резервная копия, диагностика, список отметок.
10. Полировка: плавный переход, DRM-треки, Android Auto, подпись APK, релиз, фоновый радар с уведомлением.

## Статус

- Этап 0: готов.
- Этап 1: готов. В `src/core` скопированы без правок логики: `waveTypes`, `trackIdentity`, `waveGenres`, `waveMood`,
  `waveLinks`, `wavePicks`, `waveTaste`, `waveTexts`, `tasteParams`, `libraryMix`, `pageSources`, `wave/sources`
  и их тесты (93 теста). `src/core/wave.ts` это фасад с теми же реэкспортами, что у desktop-файла `wave.ts`.
  Правки относительно desktop: типы `WaveTrack` в `trackIdentity` берутся из `waveTypes`, путь фикстуры в тесте.
  Синхронизация с desktop пока ручная; общий пакет вынесем позже.
  Не перенесено сознательно: `radar`, `radarSchedule`, `tasteModel`, `historyIndex`, `recommendStore` (нужно хранилище,
  этапы 6–7), `wave/quiet` (этап 10), всё, что работает с DOM страницы.
- Этап 2: готов. Что есть:
  - `src/api`: клиент api-v2 (`client.ts`) с диспетчером из `core/pageSources`, ключом клиента и токеном, повтором после
    401 с новым `client_id` и тайм-аутом; таблица эндпоинтов (`endpoints.ts`); `client_id` берётся обычным GET
    `https://soundcloud.com/` с User-Agent настольного браузера (`clientId.ts`); методы `me`, `likedIds`, `tracksByIds`,
    `searchTracks`, `relatedTracks`, `resolve` (`soundcloud.ts`).
  - `src/auth`: вход в WebView на `soundcloud.com/signin` с настольным User-Agent и скриптом, который ловит токен
    из заголовка Authorization запросов к api-v2, из cookie `oauth_token` и `client_id` из hydration (`loginScript.ts`);
    ручной ввод токена как запасной путь; проверка токена запросом `/me`; хранение в `expo-secure-store`.
  - Экраны: главная показывает лайки после входа, `/login` вход.
  - Проверено 12.10.2026 без входа: публичные эндпоинты отвечают 200, `/me`, `/me/track_likes/ids`,
    `/me/play-history/tracks`, `/me/playlist_likes/ids` отвечают 401.
  - Не проверено на реальном аккаунте и устройстве: поймает ли скрипт токен при входе, работает ли вход через Google
    в WebView (Google может блокировать встроенные браузеры; тогда запасной путь по токену).
  - Для этапа 3: у части треков нет открытого AAC. У трека из проверки были `hls audio/mpeg` и `progressive audio/mpeg`,
    а AAC только с шифрованием (`cbc/ctr-encrypted-hls`). Выбор потока: progressive mp3, потом hls mp3, потом hls AAC,
    шифрованное только как «недоступно».
- Этап 3: готов. Что есть:
  - Движок: `expo-audio` (ExoPlayer), один плеер на приложение, фон через сервис `mediaPlayback` и управление с экрана
    блокировки (`expoEngine.ts`). Выбран вместо `react-native-track-player`: тот не обновлялся с августа 2025, до RN 0.82+
    с одной новой архитектурой, и совместимость с RN 0.86 нельзя проверить без Android SDK. Ограничение `expo-audio`:
    в шторке пауза и перемотка на 10 с, кнопок «дальше»/«назад» нет (в приложении они есть).
  - `src/player`: `stream.ts` (выбор потока: progressive mp3, hls mp3, hls AAC, потом отрывки; шифрованные без открытых
    потоков это «недоступно»), `queue.ts` (очередь, повтор), `controller.ts` (переходы, пропуск недоступных, повтор
    запроса потока при ошибке, подготовка следующего трека, сохранение сессии), `session.ts` (снимок без потоков).
  - Экраны: мини-плеер на всех экранах, полный плеер (модально), очередь с переносом и удалением; лайки на главной
    запускают очередь с нажатого трека. Сессия восстанавливается после запуска на паузе.
  - Проверено на живом API 12.10.2026: у обычных треков progressive и hls mp3 отдают 206 на Range; у трека лейбла с
    шифрованным AAC оба открытых потока дают 404.
  - Не проверено на устройстве: звук, шторка, фоновая игра дольше 3 минут, разрешение на уведомления (Android 13+),
    ручной вход. Манифест после `expo prebuild` проверен: `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `AudioControlsService`,
    `POST_NOTIFICATIONS`, без `RECORD_AUDIO`.
  - CI: сборка APK для этапов 0 и 1 в Actions прошла. Проверка desktop-репозитория (`windows.yml`) падала из-за
    `.md` в `mobile/`: `check:repo` теперь допускает `mobile/*.md`, а `windows.yml` не запускается на изменениях только
    в `mobile/`.

  - Вкладки `src/app/(tabs)`: главная (полки «Недавно слушал» и «Лайки»), поиск (треки и артисты, по нажатию «Поиск»
    на клавиатуре, без дозагрузки: 50 треков и 20 артистов), библиотека (лайки с подгрузкой по 50 и история).
    Без входа личные экраны предлагают войти; поиск и артист работают без входа.
  - Артист `src/app/artist/[id].tsx`: шапка, «Играть», популярное и новое (`user`, `userToptracks`, `userTracks`).
  - Меню трека (долгое нажатие или «⋯»): играть следом, в конец очереди, играть похожее, к артисту, поделиться.
    Лайк и дизлайк не сделаны: клиент API умеет только GET, нужны POST/DELETE и проверка на аккаунте.
  - Общее: `useLoad` (загрузка с повтором), `Loadable`/`RequireAuth`, `TrackRow`, `Shelf`.
  - Не проверено на устройстве; `GET /users/{id}` без входа на живом API не проверялся. Плейлисты библиотеки
    (`/me/library/all`) не сделаны. Лайк и «Не нравится» из меню сделаны в этапе 5.
- Этап 5: готов в урезанном виде («Моя волна» без вкуса, он в этапе 6). Что есть:
  - `src/wave/engine.ts`: подбор на `core` (`acceptCandidate`, копии и семьи версий, `pickSpaced`, `isNewArtist`):
    зёрна из истории и лайков (по одному на артиста, три за проход), `relatedTracks`, страницы жанра (recent и search
    по курсору), режимы «Похожее»/«Новое», волна от трека (с запасом из треков артиста) и от артиста (его лучшее первым).
    В этапе 5 найденное тасовалось; вкус, станция трека, подборки SoundCloud, соседи, настроение и «Моя музыка»
    добавлены в этапе 6.
  - `src/wave/session.ts`: первая пачка из 10 заменяет очередь, дальше дописывается, когда впереди ≤3 трека (повтор
    после сбоя через 15 с). Если человек включил своё, волна выходит. Причина трека (`reasonText`, пока только
    русский) видна в плеере. Режим и жанр хранятся в `expo-sqlite/kv-store`. После перезапуска приложения волна не
    продолжается: очередь восстанавливается обычной.
  - Экраны: вкладка «Волна» (режим, жанр, старт/стоп), кнопка на главной, пункты меню трека «Волна от трека/артиста».
  - Лайки: `PUT/DELETE /users/{id}/track_likes/{track}` (`sc.setLike`, клиент теперь умеет метод), сердечко в плеере и
    пункт меню; id лайков до 1000 свежих. Путь и методы не проверены на аккаунте.
  - «Не нравится» и «Скрыть артиста» (`src/wave/marks.ts`): у SoundCloud дизлайка нет, как и на desktop это местный
    запрет, хранится на телефоне, убирает трек из очереди и из подбора. Список отметок для просмотра придёт в этапе 9.
  - Сборка: `expo export --platform android` проходит (JS в Hermes-байткод); APK локально не собирался, нет Android SDK.
- Этап 6: готов, с оговорками ниже. Что есть:
  - SQLite (`expo-sqlite`, файл `wave.db`, `src/store`): таблицы `plays` (журнал прослушиваний с описанием трека
    в строке) и `marks` (отметки вкуса). `history.ts` пишет прослушивание (круг повтора определяется при записи),
    отдаёт `tastePlays`, `waveOrigins` (исход волны по исходной причине), `heardIds`, `recentDone`, отметки.
    Проверяется в тестах на `node:sqlite` тем же SQL. Настройки, лайки в памяти и сессия плеера остаются в kv-store.
  - Журнал `src/wave/tracker.ts`: смена играющей записи закрывает прошлую. «Дослушал» это конец в последние 3 секунды,
    остальное пропуск человеком; меньше секунды звука не пишется; уход приложения в фон пишет «остановку» и счёт
    продолжается. Записи несут источник (`wave:similar`, `wave:library`, `app` ...), причину, исходную причину и пресет
    (`QueueItem.meta`). Ранний пропуск волны сразу учит идущую волну (`feedback`).
  - Вкус: `src/core/tasteModel.ts` (копия `buildTaste` и `playWeights` с desktop без правок логики) и
    `src/wave/taste.ts` (профиль по журналу за год, отметкам, лайкам, подпискам и исходам источников, кэш 30 минут).
    Без журнала вкус строится по последним 200 лайкам и подпискам, так что старт не пустой. Отметки «Не нравится» и
    «Скрыть артиста» теперь дают минус вкусу (копия в таблице `marks`).
  - Подбор (`src/wave/engine.ts`) теперь по вкусу: `tasteOrder`, причины «любимый артист/тег» (`applyTasteReasons`),
    зёрна с весом по вкусу, поправка источников `sourceBias`, правило «кириллица от неизвестного артиста только от
    похожих артистов, подборок и соседей», уверенные места 1-3, поправка сессии от пропусков и лайков.
  - Новые источники: станция трека (`discover/sets/track-stations:<id>`), подборки SoundCloud (`mixedSelections`,
    `core/wave/sources` через shim `localStorage` на kv-store), похожие артисты (лучший трек похожего артиста любимого,
    начало волны от последнего дослушанного за час, у волны от артиста лучшее восьми похожих), находки соседей по
    вкусу (`trackCategory` likers и `userTrackLikes`, кэш на 3 дня). Соседи на desktop живут в полке подборок дня
    (этап 7), здесь они дополнительно идут в обычную волну по 4 трека за проход.
  - Настроение: пять пресетов (словарь `waveMood`), метки настроения ищутся на сайте, подходящее идёт в пул,
    остальное в добивку после двух проходов; перенос от исполнителя и соседей по зерну.
  - «Моя музыка» (`src/wave/library.ts`, блок на вкладке «Волна»): лайки и плейлисты (свои и сохранённые) на выбор,
    режимы «По порядку», «Перемешать», «Умное» (три своих, один похожий), слышанное за 3 дня в конце, настройка по
    аккаунтам в kv-store. Пул берётся из `core/libraryMix` без правок.
  - Не перенесено сознательно: плейлисты в модель вкуса, «убрать из вкуса» (сделано в этапе 8), настроение по плейлистам трека и
    штраф пресета за пропуски, развилки по серии пропусков (П7), журнал разбора выдачи, «Давно не слушал»
    (`forgottenPicks`, нужен счётчик любви), импорт истории сайта в журнал (дат прослушивания у `tracksOf` нет),
    спаны покрытия (`covered` всегда пусто, модель берёт `heard`). Лайки в «Моей музыке» до 1000 свежих, плейлист до 500.
  - Не проверено на устройстве и живом аккаунте: `expo-sqlite`, station/mixedSelections/likers на реальных ответах,
    скорость сборки пула на тысячах лайков.
- Этап 7: готов, с оговорками ниже (279 тестов, `tsc` и `expo export --platform android` проходят). Что есть:
  - Подборки дня (`src/wave/shelf.ts`, полка на главной `MixShelf`, экран `/mix/[key]`): «Находки дня» (похожее на 8 любимых,
    каждым третьим лайк соседей по вкусу), «Лайкнули твои артисты», «Давно не слушал» (теперь с весом любви: дослушано,
    круги повтора, ранние пропуски по журналу, `shelfInputsOf`), до 8 жанров из вкуса, «Плейлист момента» на шесть часов
    суток. Собирается раз в сутки, снимок (номера, названия, обложки) в kv-store; после первого обхода соседей полка
    пересобирается при следующем открытии. Подборка играет волной `{kind: 'library'}`: её треки по порядку, дальше
    похожее; причина у каждого трека своя (`own[].reason`, поле добавлено в engine). Нажатие на трек в списке
    подборки начинает с него.
  - Радар релизов (`src/core/radar.ts` копия чистых частей desktop `radar.ts`, `src/wave/radar.ts`, экран `/radar`): свежесть
    версии, оценка по вкусу, группы исполнителей, архив, пачки без дат, «Новые загрузки», «Ремиксы и эдиты». Выпуск
    собирается по запросу, а не по пятницам: подписки и любимые аккаунты из вкуса (до 100, по 20 последних загрузок,
    4 запроса разом в фоновой очереди), окно 7 дней, хранится 6 часов, «Пересобрать» на экране. «Уже слышал» в конец.
  - Чарты (`/charts`): `/charts/selections` отдаёт Music Charts US и UK по десять плейлистов (жанры, New & Hot, Artist Pro).
    Проверено 12.10.2026 без входа: 200. Старые `/charts?kind=top` и `kind=trending` с жанром дают 404 или 400, работает
    только `kind=trending&genre=soundcloud:genres:all-music`, он не используется. Состав открывается экраном плейлиста.
  - Плейлисты: вкладка «Плейлисты» в библиотеке (свои и сохранённые, список тот же, что в «Моей музыке»), экран
    `/playlist/[id]` (до 500 треков по порядку сайта, «Играть», игра с нажатого). `sc.playlistTracks`, `sc.likedTracks`.
  - Набор из меню трека (до 5, «Добавить в набор»): плашка на главной включает волну по похожему на все сразу.
    Живёт в памяти приложения, после перезапуска пуст.
  - Не перенесено: плановый выпуск по пятницам, фоновая задача и уведомление радара (этап 10, нужен `expo-task-manager`),
    поиск свежего по любимым участникам, архив выпусков, «Все найденные», копии одной записи в радаре; запоминание
    сыгранного из «Давно не слушал» за сутки (П11); свежие лайки за 30 дней не исключаются из «Давно не слушал» (дат лайков нет);
    лайки в подборках до 1000 свежих. Остальные «аддоны» desktop (язык, аккаунты, инкогнито, вебхуки,
    резервная копия, диагностика, список отметок) остаются этапу 9.
  - Не проверено на устройстве и живом аккаунте: сборка полки на реальных лайках (до 20 запросов на лайки плюс 8 на
    похожие), `/me/followings`, `userTracks` с `display_date`/`release_date` у реальных подписок, скорость радара на
    100 аккаунтах, `PUT` лайка. Внешний вид карточек (коллаж, тон, подпись) не смотрели на экране.
- Этап 8: готов, с оговорками ниже (304 теста, `tsc` и `expo export --platform android` проходят; `expo lint` не настроен,
  eslint в проекте нет). Что есть:
  - «Убрать из вкуса» (`src/wave/tasteOverrides.ts`, экран `/taste`, ссылка на вкладке «Волна»): аккаунты и теги, которые
    модель вкуса не учитывает (`buildTaste` получает их третьим аргументом, как на desktop). Хранятся в kv-store по
    аккаунтам (до 20). Экран показывает, кого и что волна ставит чаще, кнопку «Убрать из вкуса» и список убранного с
    возвратом. `Taste.view` считает вид заново при каждом открытии, `Taste.setRemoved` сбрасывает кэш профиля.
    Идущая волна держит прежний профиль до перезапуска.
  - Штраф пресета (`src/wave/presetMarks.ts`): ранний пропуск в волне с настроением копится по аккаунту и тегам именно для
    этого настроения (до 10, не больше 300 ключей), в оценке трека `−0.5 × min(2, пропусков аккаунта)` и так же по долям
    тегов. Хранится в kv-store (`wave.moods.v1`) и переживает перезапуск; у волны от трека, артиста и подборки пресета нет.
  - Признак серии пропусков (П7): на втором и третьем раннем пропуске подряд общий признак (пометка версии, язык, главный
    жанр, чужой канал; `seriesTrait` из core) прижимается до конца волны, `−1` к оценке. Подсказка внизу экрана с
    «Отменить» (8 секунд). Дослушанный от 30 секунд трек обрывает серию и снимает прижим своих признаков. Признаки зерна
    и выбранный жанр не прижимаются.
  - Развилка «Куда дальше?» (П8): три быстрых (быстрее 5 секунд) пропуска подряд открывают лист с четырьмя-пятью

## Риски

- api-v2 не документирован, `client_id` меняется, возможны 429.
- Треки с Widevine (`ctr-encrypted-hls`) на старте помечаются недоступными.
- Плавный переход и тихие края требуют отдельной реализации (два плеера).

## Сборка

Локально нужен JDK 17 и Android SDK. Без них APK собирает GitHub Actions
(`.github/workflows/android-apk.yml`), файл лежит в Artifacts запуска.

Релиз: тег `mobile-vX.Y.Z` (подробности в начале `android-apk.yml` и в статусе этапа 10).

```
cd mobile
npm ci
npm run typecheck
npm test
```
